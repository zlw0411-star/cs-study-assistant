# 桌面资料整理指南

## 首期范围

目标是将一份资料整理为可回查的结构与知识点，不是聊天、答题或联网知识补全。桌面版提供两层：默认的无模型本地目录，以及按需调用模型的智能整理。支持 PDF、DOCX、TXT、Markdown，每份文件独立处理；暂不支持 PPT/PPTX、旧版 DOC、图片 OCR 或跨文件合并。可以先将其它格式导出为可选择文字的 PDF 或 DOCX。

## 使用流程

1. 双击项目根目录的 `启动桌面版.cmd`；首次安装方式见 [desktop.md](desktop.md)。
2. 选择“导入资料”，或将单个文件拖进窗口。查看文件格式、字符数、来源片段及可提取文字的页数/段落起点；这些不是原文件总页数或总段落数。
3. 先检查右侧提取原文。存在警告时点击“查看全部提取警告”；全扫描 PDF 会拒绝导入，混合 PDF 会保留可读取页并列出缺失页。复杂公式、图表、表格和阅读顺序需要对照原文件。
4. 无已保存智能报告时默认进入“本地整理”，自动打开“目录”标签。选择章节节点或来源链接即可核对原文，不需要配置模型，也不会联网。无可靠标题时展示“原文分段”，不是模型归纳的大纲。已有智能报告的资料默认打开智能模式，可在报告区下拉框切回本地。
5. 需要摘要和知识点时，在“模型设置”填写 OpenAI Chat Completions 兼容服务地址、模型 ID 和 API Key，然后显式点击“在线智能整理”。所选资料的全部可提取文字会分批发给配置的服务，可能多次计费；按钮旁流程中有常驻提示。切换模式本身不会请求模型。Pi 中的 ChatGPT 订阅登录不会自动成为本应用的模型配置。智能报告中的知识点按章节呈现，缺少章节信息的旧条目列在“未标注章节”。
6. 查看“摘要”中的警告和“查看整理详情”中的未引用来源，必要时自行核对遗漏。导出 Markdown 或 JSON 以保留来源索引；最终导出路径已经存在时，需要确认覆盖。

节点包含多个来源时先定位第一个，其余可通过来源链接选择。两种模式都可导出，默认文件名分别为 `文件名-outline` 和 `文件名-analysis`。手动模式选择在本次窗口会话内按资料记忆；重开应用后仍按是否存在智能报告决定默认模式。

## 本地规则与限制

- 从当前已保存的提取文字识别 Markdown `#` 标题（也包括 DOCX 提取阶段保留的标题标记）、有明确分隔的“第X篇/章/节”和 `1.1` 等数字层级。中文章下的数字小节会按上下文嵌套，不自动补不存在的中间章节。
- 排除代码块、缩进代码、明显正文和公式行；允许 C++、B+树、I/O 等标题词语。分片续行保守处理，避免把代码行尾误认标题。纯文本规则不保证识别所有真实标题，不识别 PDF 书签或字体样式；无分隔的“第一章绪论”等可能漏识别。
- 前言、无标题或无法确认标题的范围按原文来源导航，明确标为“原文分段”。不改写正文，不编造摘要、定义、知识点或学习建议。
- 最多识别 300 个标题、600 个导航节点，标题最长 120 字符；超限明确提示并退回分段导航。所有输入来源仍有导航入口，章节边界落在同一来源片段内时，多个章节可以引用同一片段，不表示精确行级定位。
- 本地层不调用网络、模型或额外依赖；只有资料导入和导出涉及本机文件。生成结果只在内存中，重开后从已存文字重建，绝不写入智能报告表。智能报告损坏时仍可继续浏览和导出有效的本地来源。

## 智能整理结果的含义

- **原文标题**：模型提出的标题与其引用原文的独立行匹配（忽略空白差异及 Markdown 标题标记）。仅出现在正文中的词语不会通过验证。PDF 的断行本身并不证明真正章节结构，仍须核对原文件。
- **自动归纳**：模型重组或缺乏原文独立标题行证据的标题。层级优先沿用资料，不把自动重组伪装成原文章节。
- **知识点**：保留名称、说明和来源；按有依据的内容追加章节、定义、核心要点、公式、适用条件。不要求每个条目凑齐字段，不补充资料未给出的背景知识或例子。说明及定义均为 AI 归纳，非逐字引用。
- **长资料**：分段整理后逐级合并，阶段间保留新增字段；优先在换行处分段。只在内容完全一致且章节明确相同或无章节但证据重叠时，本地合并重复知识点，避免跨章节同名误合并。模型本身仍可能遗漏、误解或错误合并。
- **已处理来源**：模型中间结果通过输入范围声明验证，不代表内容已完整理解。
- **已引用来源**：最终大纲/知识点实际引用的来源 ID 数量，不代表其中全部内容都被整理。未引用 ID 完整保存在报告元信息并可通过详情滚动查看。

## 存储与兼容

数据库和公共来源数据结构不变，无需迁移或重建原有资料库。已保存资料不会自动重新提取，旧报告也不会自动重新分析。新提取效果需重新导入文件；相同文件会去重，若确需重新提取，请先备份所需原件和报告，再删除旧记录、重新导入。重新分析会使用当前已存储的提取文字，不会更新提取结果。

新增报告字段向后兼容：

- `metadata.mode="local"`：本地结构报告，含 `heading_count`、`outline_basis`（`headings` / `source_segments` / `mixed`）。本地 `generated_at` 为资料导入时间，用于稳定重建，不是模型生成时间；兼容计数字段仅描述导航来源。
- 本地 `outline[].kind`：`heading` 或 `source_segment`；分段入口不应解释为语义标题。
- `outline[].origin`：`original` 或 `inferred`，智能报告缺省视为归纳；本地分段节点虽为 `inferred`，界面会按 `kind` 明确显示“原文分段”，不是 AI 归纳。子节点同样适用。
- `knowledge_points[]`：可选 `chapter`、`definition`、`key_points`、`formulas`、`conditions`。
- `metadata.referenced_source_count`、`metadata.unreferenced_source_ids`：引用统计及完整未引用来源列表。

JSON 导出保留完整报告与来源索引，Markdown 导出包含新增字段、提取警告、处理/引用统计和来源全文。密钥不写入数据库或导出。资料本身或来源读取失败时清空旧状态并禁用分析和导出；只有智能报告读取失败时回退本地目录并提示，不覆盖损坏记录。智能整理失败或取消不会覆盖已有成功报告，也不会损坏本地目录。

## 离线验收与边界

新增测试见：

- `tests/test_material_extraction.py`：真实内存 PDF/DOCX/文本、标题/表格顺序、编码、修订、损坏和安全边界。
- `tests/test_analysis_organization.py`：字段类型与大小限制、map/reduce/final 传递、标题降级、保守去重、未引用提示及大量警告汇总。
- `tests/test_desktop_organization.py`：新旧报告渲染、来源定位、导出、读取失败及覆盖取消。
- `tests/test_organization_flow.py`：四种真实合成格式经过后台任务、HTTP MockTransport、持久化、离屏 Qt、原文点击、MD/JSON 导出及重开读取；检查文件隔离和密钥不落盘。
- `tests/test_organization_regressions.py`：正文子串不算原文标题、TXT 分页符、安全错误提示、客户端清理失败保留结果、多未引用来源的紧凑布局和完整详情。
- `tests/test_local_organization.py`：纯本地规则、四格式真实提取、混排层级、代码/公式/续片边界、标题超限、全部来源可达和 600k 字符性能。
- `tests/test_two_layer_desktop.py`、`tests/test_two_layer_failures.py`：无配置/无网络本地使用、两层独立导出与重开、按资料记忆、智能失败/取消不覆盖、本地降级可用、模式状态和调用前费用提示。

测试不调用真实模型，不验证模型的实际知识提取质量，也不能替代真实教材、复杂公式版面或人工鼠标验收。服务端对格式的兼容性、网络、费用和语义质量需针对所选提供方另行评估。运行全量测试的方法和最新结果见 [desktop.md](desktop.md)。
