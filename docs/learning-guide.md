# 八周项目代码学习：每周 2–3 小时

这份计划教你逐步读懂真题学习台的 Python 代码，不替代 408 备考。每周这 2–3 小时只用于代码阅读、自己修改一个小功能和运行检查。实际刷真题与复习知识点另行安排，不计入这段项目学习时间。

| 周 | 主题与阅读 | 自己修改一个小功能 | 检查与记录 |
|---|---|---|---|
| 1 | 看 `study_assistant/exam_types.py`，读懂 `PaperInfo` 和 `QuestionInfo` 字段 | 给页面增加一条自己写的题目定位说明 | 画出题目对象从服务到页面的路径，解释页码和状态字段 |
| 2 | 阅读 `ExamService.import_pdf` 和题目拆分逻辑 | 改善一种PDF导入警告的中文提示 | 用可提取和低文字样本记录各自的处理结果 |
| 3 | 阅读 `list_questions`，追踪科目、年份、考点、状态如何组合筛选 | 增加一个简短的筛选结果说明 | 设计两组筛选条件，记录题数变化及其原因 |
| 4 | 阅读原卷页渲染 `render_page` 和题目页码字段 | 给页码图片增加一个你认为有用的上下文提示 | 用两道题核对列表页码和PDF原页是否对应 |
| 5 | 阅读 `set_classification`、`get_topic_progress` 和知识卡 JSON | 为一个知识卡增加一条“解释为什么”的问题 | 解释自动分类、手动修正和考点反思记录的区别 |
| 6 | 阅读 `save_topic_progress`、`save_progress` 与薄弱考点统计 | 调整原理记录或变式记录的帮助文字 | 比较错题/复习状态与原理迁移自检记录如何分别保存 |
| 7 | 阅读 AppTest 和服务测试中的边界用例 | 为一条你修改过的行为增加一个测试 | 运行相关测试，并记录失败时从哪里开始排查 |
| 8 | 回看架构图、产品范围和你前七周的记录 | 给筛选区补一条让新用户更容易理解的帮助文字 | 用三分钟解释一次题目从导入、分类到保存学习记录的流程 |

## 与真题练习分开安排

日常备考与每周 2–3 小时的项目代码学习分开安排。基础复习后挑一个考点做三题，先独立作答，再对照原卷与已有答案；把错题标为“需复习”，写下是概念混淆、漏看条件还是推导错误。之后重建知识原理，回答卡片里的“为什么”，说清适用条件，再改变条件推导一个变式。每个考点的原理和迁移解释只记录一次。最后换另一个年份做一道未练的新题，检查能否在不同条件下推导；能讲清理由时，再把本题自评为“本题已理解”。状态是自己的学习记录，不是系统判断的掌握率。

## 十个代码自检问题

1. `QuestionInfo` 的 `start_page` 和 `end_page` 如何用于显示原卷图像？
2. PDF 导入时，系统如何识别页码或文字量不足的页面？
3. `list_questions` 支持哪些筛选条件？多个条件组合时页面如何传给服务？
4. 答案 PDF 怎样与原卷关联？为什么答案页码不能直接按原卷页码推算？
5. `topic_ids` 和 `matched_keywords` 分别表示什么？
6. 自动分类和 `classification_manual` 有什么区别？用户怎样改分类？
7. `new`、`review`、`mastered` 三种状态由谁选择？
8. `unresolved_wrong` 为什么只统计未掌握错题？历史上做错但已自评掌握的题会怎样排序？
9. 知识卡的 `prerequisites`、`checklist` 和 `common_mistakes` 分别在页面何处使用？
10. 为什么回忆版默认不进入题目列表？如何在界面中明确选择包含它？

把不能独立回答的问题记下来，回到实际代码和本地材料核对。每个小改动都由你亲自完成、运行和解释；工具协助可以用于查资料或复核，但不能替代自己理解修改结果。
